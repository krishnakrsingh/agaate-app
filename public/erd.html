Safeguard 01
Two-Man Geofence Rule
Any change to a farm's geofence boundary requires sign-off from a second Super Admin. Neither can approve alone. The request sits in a LocationChangeRequest queue until both sign.
Safeguard 02
GPS Distance Check
When a Farm Officer punches attendance, the system checks their GPS coordinates against the farm boundary. Distance >150 m flags an AttendanceException for Farm Admin review — automatic, no override possible.
Safeguard 03
PHI Harvest Lockout
If the days-since-last-chemical-application are fewer than the crop's Pre-Harvest Interval, the harvest logging screen is disabled entirely. The count-down is visible; the button is not.
Safeguard 04
Stock Pre-Flight Check
Before a task is dispatched to the field, the system checks whether all required materials are in warehouse stock. If any item is depleted, the task stays blocked with an explicit stock-out message.
Safeguard 05
Camera Enforcement
The mobile app blocks gallery uploads. Every attendance photo and task proof must be taken live with the device camera. This is enforced at the hardware API level, not just UI.
Safeguard 06
Critical Incident Escalation
A Critical incident that the Agronomist has not acknowledged within 120 minutes is automatically escalated to the Super Admin. No human step required — the timer is server-side.

Section 04

Operational Lifecycle Flows

Four end-to-end sequences that show how the roles, features, and data entities work together in a real day on the platform.

Flow 01
Morning Muster to
Field Dispatch
  1. Farm Officer opens the mobile app at the farm gate. Takes a live selfie. GPS coordinates are captured automatically.
  2. System checks GPS against geofence. If within 150 m: Attendance is recorded. Beyond: AttendanceException queued.
  3. Farm Admin opens the Muster dashboard on the web portal. Sees the day's list with any exceptions flagged in amber.
  4. Farm Admin reviews each exception (was the officer legitimately off-site?), approves or marks absent. DailyCrewMuster locked.
  5. Farm Admin creates today's Task list — assigns officers, plots, materials required.
  6. System runs stock pre-flight on each task's material list. Any shortfall blocks that task with a stock-out message.
  7. Officers see their task queue on mobile. Field work begins with digital instructions instead of verbal briefing.
Flow 02
Agronomy Plan to
Stock Depletion
  1. Central Agronomist reviews last week's CropMonitoring data and scouting alerts on the web portal.
  2. Agronomist creates a new AgronomyPlan for the affected plots — 7-day rolling — with daily prescriptions (chemical name, rate, method).
  3. Prescriptions carry PHI days. The system logs the last-application date when execution is confirmed.
  4. Farm Admin aligns the Task queue to the agronomy prescriptions — dispatches chemical application tasks to officers.
  5. Farm Officer receives the task on mobile. Executes the spray run. Uploads photo proof and logs volume used.
  6. System creates MaterialUsage record, decrements InventoryItem quantity. If stock drops below threshold: low-stock alert to Farm Admin.
  7. PHI clock starts. Harvest is locked until the chemical withdrawal period expires. Count-down visible on the plot's harvest screen.
Flow 03
Pest Scouting to
Incident Closure
  1. Farm Officer walking Plot B notices unusual leaf damage. Opens the mobile app's Monitoring screen.
  2. Logs a CropMonitoring entry: health score 2 out of 5, notes "leaf curl, possible mite infestation", attaches 3 photos.
  3. Health score <3 triggers an instant push alert to all agronomists with access to this farm.
  4. Central Agronomist sees the alert. Reviews the photos and notes on the web portal within minutes.
  5. Agronomist files an Incident — type: Pest, severity: High. Adds an IncidentFollowUp with mitigation instructions.
  6. Agronomist updates the AgronomyPlan to add an emergency miticide prescription for the next 2 days.
  7. After the treatment task is executed and monitoring score recovers above 3, agronomist closes the Incident. Full audit trail preserved.
Flow 04
Harvest to
Unit Economics
  1. Plot A's Milestone reaches Stage 4 (Harvest Ready). The agronomist marks the milestone as complete.
  2. Farm Officer opens the Harvest screen on mobile. System checks PHI compliance for the last chemical applied to Plot A.
  3. If PHI clear: officer enters harvest weight, batch reference, and picker count. HarvestLog created.
  4. System creates InventoryTransaction — produce added to warehouse. Stock updated in real time.
  5. Farm Admin sees the HarvestLog and cross-checks against expected yield from the agronomy plan.
  6. System aggregates MaterialUsage + LabourUsage + ExpenseLog for the CropCycle. Calculates cost per kilogram.
  7. Super Admin views macro P&L — Plot A's harvest revenue vs cost per kg visible at the executive dashboard. CropCycle closed.
