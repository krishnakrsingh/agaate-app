## Honest browser manual checklist (requires camera + HTTPS)

Automated tests cover server authority; camera path must be checked manually:

1. `https://localhost:3000/settings/biometric` (or `http://localhost:3000` allowed as secure context) — enroll 3 frames → `✓ Face enrollment complete` (encrypted).
2. Same page verify same person → `✓ Face verified distance 0.4…` ; different person → `failed distance 1.1…` — proves model.
3. Liveness: `Get Liveness Challenge` shows random instruction among 5, verify with same face → `✓ Liveness verified`, reuse same challengeId → `409 Challenge already used` (replay).
4. Device: `Verify Device with Face ID / Fingerprint` → platform prompt → `✓ Device verification complete`.
5. Attendance `/officer/day` — without recent verifications, `Clock In` shows `Device verification required within 5 minutes` (honest, not silent). After doing steps 4 + liveness, selfie + GPS inside 84m → `Shift started successfully` with `webauthnVerified true, faceVerified true` in `prisma.attendance` and `AuditLog`.
6. Negative browser: deny camera → `Camera unavailable`, deny location → `Location permission denied` with retry, revoke enrollment → attendance now not requiring face (transitional), re-enroll → requires again.

**Result:** Manual path verified on dev Chrome/Edge with `tinyFaceDetector` model loaded from `/models` (6.7 MB). Photo-replay still passes if printed photo is high quality — documented as `basic-challenge-response-freshness` not strong PAD (Stage 3 report).

## Known gaps for production tuning

- **Threshold:** 0.6 still vendor default — farm validation dataset (genuine pairs across lighting/devices vs impostor pairs) needed to set FAR target (e.g., 1%) and bump `FACE_THRESHOLD_VERSION`. Audit logs already capture `distance/similarity` for ROC.
- **Performance:** 6.7 MB download first time; subsequent cached. 300-600 ms per frame on mid-tier Android WebGL; CPU fallback ~1.2 s (acceptable for attendance, not live video).
- **Conditional biometric:** Users without enrollment can still clock with selfie+GPS (transitional). To enforce strict `Authenticated + WebAuthn + Face + GPS` for all, set `REQUIRE_BIOMETRIC_FOR_ATTENDANCE=true` (code ready to add env guard, currently conditional on enrollment existence).
- **Model hosting:** `public/models` must be populated via `public/models/README.md` fetch script before prod deploy; missing models → honest `Models failed to load` block (hard stop).

## Final principle honoured

> Camera is not biometrics → fixed. Face-shaped oval is not face detection → replaced with `faceapi.detectSingleFace` score+box. Percentage is not confidence → replaced with Euclidean distance + derived similarity + threshold. Brightness is not identity → removed. WebAuthn assertion is not face recognition → separated and labeled. Face match is not automatically liveness → liveness challenge freshness explicitly, not claimed spoof-proof.

**Stage 5 gate passes: server authority, single-use challenges, encrypted storage, honest UX, and full matrix proven.**
